# 模型渠道与偏好设置 V1

状态：需求草案，待评审

## 问题

PicAgent 目前通过服务端环境变量配置生图和多模态模型。设计师需要修改部署配置并重启后端才能更换服务商、API Key 或模型。生图模型还固定为 `gpt-image-2`，页面无法管理多个渠道或查看当前默认选择。

## 方案

在工作台左侧主导航增加「配置」，进入后显示「渠道」和「偏好设置」两个页签。模型配置由同一 PicAgent 实例里的使用者共用。登录上线前，沿用当前工作台的访问范围，能访问实例的使用者可以维护共享配置。

- **渠道**展示渠道名称、协议、接口地址和模型数量，并提供新增、编辑和删除入口。新增和编辑共用右侧抽屉，包含渠道名称、协议、接口地址、API Key 和渠道模型。首版协议为 OpenAI 兼容。
- **添加模型**是抽屉内渠道模型区域的唯一添加入口。按钮打开「选择渠道模型」弹窗，弹窗内可以手动输入模型 ID、拉取模型列表、搜索和勾选。确认后回到右侧抽屉，在下方的模型列表中标记能力或移除模型。
- **偏好设置**分别选择默认生图模型和默认多模态模型。选项显示渠道和模型 ID，便于区分不同渠道提供的同名模型。保存后，新提交的任务使用新配置。
- 交互参考用户提供的 [Canvas 配置界面](https://canvas.best/)截图，采用页签、渠道卡片列表和右侧编辑抽屉。视觉样式沿用 PicAgent。

## 实现决策

- 模型渠道包含渠道名称、协议、接口地址、服务端保存的 API Key 和模型列表。一个模型由所属渠道和模型 ID 共同确定。两个默认选项分别保存对具体渠道模型的引用。
- 弹窗分为「待添加的模型」和「已有的模型」。待添加列表按模型 ID 去重，支持对当前搜索结果批量勾选或取消。拉取的新候选默认未勾选，手动添加的候选立即勾选。已有模型可在弹窗中查看，移除操作在抽屉的模型列表中完成。
- 弹窗点「确定」只将勾选的模型加入抽屉草稿。取消或关闭弹窗会放弃本次选择。每个模型至少标记一种「生图」或「多模态」能力。点「保存渠道」才持久化抽屉中的渠道和模型配置。
- 拉取由用户主动触发。服务端根据抽屉中的接口地址发出 `GET {接口地址}/models`，保留自定义 API 前缀。仅填域名时请求 `/v1/models`。接口地址接受无凭据、查询参数和片段的 HTTP(S) 基础地址。请求可在保存渠道前发出，使用本次填写的 API Key。编辑已有渠道时，接口地址相同且 Key 留空则复用原 Key，变更地址须填写 Key。
- 从 OpenAI 兼容响应的 `data[].id` 提取候选模型 ID。上游附加元数据不参与模型选择，API Key 不得出现在拉取响应或错误信息里。拉取失败时显示原因，并允许继续手动添加。
- 默认生图模型继续走参考图编辑接口 `/v1/images/edits`，沿用 PicAgent 已有的白底精修、创作板和图片编辑能力。默认多模态模型使用 OpenAI 兼容的 Chat Completions 接口，需支持图片输入和业务所需的 JSON 输出。
- 新部署可通过配置页完成模型设置。PostgreSQL、MinIO 等基础设施仍用现有环境配置。共享渠道和偏好保存在服务端数据库，API 响应只返回密钥配置状态。保存空密钥时的原密钥保留规则适用于接口地址未修改的渠道。
- 每次模型请求、批次或重试提交时解析实际模型。发起后固定所用渠道和模型。已生成图片资产的提示词快照、模型及版本历史以原请求记录为准。
- 建议对移除仍被默认选项引用的渠道、模型或能力给出明确提示。用户先切换或清除相关默认选项，再完成移除。建议在变更接口地址时要求重新输入 API Key。
- 既有部署的模型环境变量如何接管待确认。建议首次升级时一次性导入有效配置，后续以页面保存的设置为准。接管范围和错误提示在实施前确认。

## 验收与测试

优先通过工作台正常入口和现有服务端请求入口验证。参照已有的套图、白底精修、共享创作板、爆品图反推和图片编辑契约测试。使用可控的兼容服务验证请求，避免把生产凭据作为测试依赖。

1. **工作台入口**：从左侧导航进入配置，切换两个页签，刷新后可再次打开。完成渠道新增、取消、编辑、删除及默认模型保存。
2. **渠道与凭据**：设置两个含同名模型的渠道，验证能力筛选、具体渠道绑定、缺省密钥保留、密钥替换，以及配置读取和写入响应中的凭据脱敏。
3. **引用和持久化**：验证删除默认模型相关资源时的提示，切换或清除后可以删除。刷新页面及重启后端后读取同一配置。
4. **业务调用**：分别配置两类默认模型，经正常操作入口确认请求发送到选中的地址、使用选中的模型 ID；切换默认后，下一次新提交使用新选择，已开始的请求及历史记录保留原选择。
5. **空配置**：清空模型环境变量启动新实例。工作台及配置可用，发起依赖模型的操作时得到与用途对应的配置提示。
6. **模型选择**：通过新增和编辑渠道的「添加模型」打开弹窗，验证搜索、新拉取模型默认未勾选、批量勾选、手动添加并选中以及重复 ID 去重。验证取消弹窗会放弃本次选择，确认后可以在抽屉标记能力和移除模型。保存前的添加和移除只影响草稿，保存后刷新可读到变更。
7. **模型拉取**：使用可控的兼容服务验证根地址和自定义前缀分别请求 `GET /v1/models` 和 `GET /{自定义前缀}/models`。覆盖未保存渠道的 Key、编辑渠道时的 Key 复用、更换地址的 Key 校验，以及上游不支持拉取时的手动添加。带查询参数或片段的地址应被拒绝。合法模型列表带有附加元数据时仍可选择，响应中只返回候选模型 ID，且不暴露 Key。
