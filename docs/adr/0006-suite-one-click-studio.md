# 商品套图一键生成工作台

商品套图改为创作功能栏、配置栏与结果区组成的一键生成工作台，让用户围绕商品输入和生成结果完成创作。系统保留两阶段规划、不可变提示词快照与一张卡一次生图请求，在事实门禁通过时自动确认结构计划，缺失必要事实时暂停补录。本决策取代旧 ADR 中与上述入口和人工确认路径冲突的条目，旧 ADR 正文保留为历史记录。

## 决策

- 取代 [ADR 0001](0001-two-phase-suite-planning.md) 的“设计师必须确认结构计划”：结构计划为 `READY_FOR_REVIEW`，且主图组及所有张数大于 0 的类别均无缺失事实时允许自动确认，快照记录 `confirmationMode: "auto"`。“其他”组零张类别的未生成原因不阻止自动确认；必要事实缺失时仍须暂停。
- 取代 [ADR 0002](0002-structure-plan-v2-and-minimal-brief.md) 的“最小简报 → 结构配置 → 结构审核 → 类别进度”单一路径，以及 [ADR 0005](0005-workbench-delivery-and-style-override.md) 所对应的“入口大厅与四步向导”两态：创建页采用功能栏、配置栏与结果区，结果区承载空态、生成中、结果与历史批次。成品交付视图保持不变。
- 白底精修和主图背景由平台的主图背景规范驱动。`pure_white_required` 使用纯白主图，禁止文字、Logo、水印和装饰，精修自动开启并锁定；`white_preferred` 优先白底或干净浅色背景，精修默认开启、可关闭；`flexible` 按平台策略允许场景底，精修默认关闭、可开启。切换平台时，非锁定情况下用户手动选择的精修开关保留。精修失败暂停并允许重试；纯白强制平台不能跳过，其他平台可用原图继续。
- 自定义结构配置按“白底主图 / 主图、卖点图、场景图、其他（AI 智能匹配）”四个分组设定张数。主图 1–5 张、默认 1 张；卖点图默认 3 张、场景图默认 2 张，前三组按精确张数校验，组内具体类别由模型按商品事实分配。主图或精确组缺事实时暂停，卖点图或场景图可补充事实或改为 0 张后继续。
- “其他”默认 1 张，用户设定的是上限；模型优先选择有事实支撑的辅助图类型，同一类别最多一张。事实不足时少出、不暂停，实际张数少于上限时在结果区说明原因。多角度外观图优先级最低，主图至少 2 张时不再生成多角度图。智能匹配以主图 1 张、详情 6 张为配置，四组不锁张数，由模型分配，“其他”仍可按事实少出。详情图合计 0–10 张，单批合计 1–12 张；主按钮按上限显示张数，结果区显示实际张数。
- 新增 `comparison`（对比图），只允许有事实依据的自身对比，如新旧款、使用前后、规格之间；不得出现竞品品牌、竞品商品，也不得使用“最好”“第一”等无依据比较。这回应 ADR 0001 删除“竞品对比”的原因：保留事实支持的自身比较，继续禁止诱导越权编造。
- 一键生成流水线依次执行按需白底精修、结构规划与自动确认、按类别串行生成提示词、建任务卡及批量生图；每张图仍独立请求。精修失败、必要事实缺失或服务中断均有恢复入口，不绕过平台规则与事实门禁。
- 一个批次就是一个方案。再次生成时新建方案，并把原图对象复制到新方案路径。允许多个批次同时生成；套图历史只展示来源为 `suite_studio` 且有流水线记录或任务卡的方案，静默创建的空草稿不进入历史列表。
- 生图画布作为独立创作功能，复用现有 XYFlow 创作板；功能栏按实现进度提供商品套图、生图画布、上架文案、爆品图反推，未实现项不显示。画布列表与打开路由为 `/create/canvas`、`/create/canvas/:suiteId`，旧 `/suites/:id/board` 跳转到新路由；套图批次在画布中打开时仍共享同一方案数据。
- 方案增加 `origin` 来源：`suite_studio` 表示商品套图，`canvas` 表示画布；默认 `suite_studio`，爆品图反推自动新建的方案记为 `canvas`。旧数据中无结构计划且任务全部来自爆品图反推的方案回填为 `canvas`，其余为 `suite_studio`。画布列表包含全部 `canvas` 方案及有任务卡的 `suite_studio` 方案；套图空草稿不出现在任何列表。
- 空白画布出图前必须至少绑定一张参考图，未绑定时禁用生成并说明原因；允许上传商品图，或从图片库选择已发布的白底图、原图。没有结构计划时显示“自由风格 / 未设置”，按方案来源区分自由画布与套图模式。纯文生图、画布模板和节点自定义编排留待后续。
- 生图分辨率与比例由当前模型能力配置 `imageOptions`（`sizes`、`aspectRatios`、`sizeMode`）决定，一期沿用全局默认 gpt-image-2，不做画布单卡切换模型。根据云端实测能力选择档位或具体像素：接受像素时按比例传像素；只接受档位时将比例写入提示词，并注明“比例由模型尽量遵循”。默认 1K、主图 1:1、详情图 3:4。
- 任务保存 `generationParams.size` 与 `ratio`，最终请求尺寸冻结到 `attempt.requestSummary.size`，执行及原样重试读取该快照；改变档位后通过单卡生成创建新请求。白底精修保持 1K，图片编辑器一期跟随源图所在任务的档位。此规则取代早期“比例只写入提示词”及“按比例出图放二期”的限制。

## Considered Options

- 保留结构计划逐次人工确认与四步向导：每批都要经历中间审核，无法形成配置到结果的一键流程；改由服务端事实与数量门禁保障自动确认。
- 把“其他”视为必须凑满的精确张数：容易以多角度图凑数或编造缺失事实，因此采用按事实少出的上限。
- 白底精修使用全局默认关闭的开关：无法表达平台强制纯白要求，因此由平台规范驱动默认值和锁定状态。
- 把空白画布视为纯文生图入口，或统一写死生图尺寸：现有链路依赖参考图，云端账号分组能力也不同，故保留参考图门禁并按模型能力配置尺寸。

## Consequences

- 结构模板需发布支持分组的新版本，服务端校验精确组张数与上限组边界；启用分组后，单类别标为可选，由分组承担必生校验。旧模板版本、计划和图片快照继续保留。
- 一键流水线需要持久化阶段、状态和配置，提供幂等启动、暂停恢复、当前批次聚合状态与历史分页；“其他”零张原因与必要事实缺失须分别处理。
- 方案来源支持套图历史与独立画布列表分流，进入画布不复制既有套图方案。生图请求必须冻结尺寸，避免配置修改改变历史重试。
- 一期按商品套图及分辨率/比例、生图画布独立入口、上架文案三个里程碑验收；上架文案的独立资源、平台规则、事实约束与版本化决策留到里程碑③的 ADR 0007。
