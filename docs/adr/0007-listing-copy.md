# 商品上架文案生成

上架文案和商品套图使用相同的商品事实，但交付内容、平台限制和重试周期不同。本文细化 [ADR 0006](0006-suite-one-click-studio.md) 的上架文案里程碑，不改变套图的两阶段规划与出图门禁。

## 决策

- 使用独立的文案任务、输入图片和文案版本资源。套图附加功能使用该批次的原图与配置，并在结构计划确认后并行生成文案；文案失败不改变套图状态。独立入口可上传至多 6 张商品图或选用已有批次。独立上传首张图时静默创建草稿，图片放在 `listing-copies/<jobId>/inputs/`，不创建套图方案；从未生成的草稿不进入文案历史。
- 平台的标题字数上限、要点条数上限、禁用词和搜索词支持由 `platform_profiles.listing_copy_rules` 管理。服务端确定性校验模型结果和手工编辑；超限或含禁用词时拒绝当前结果，允许重试。
- 文案只使用商品图可见信息和用户提供的卖点，不编造参数、认证、功效或价格。缺少信息时留空并提示补充。支持五点描述的平台可返回五点，国内平台展示卖点短句；不支持搜索词的平台不返回该字段。
- `general.listing-copy` 使用独立的 `listing_copy` 阶段，沿用提示词模板的版本发布流程。每次成功生成、重新生成或保存编辑都追加文案版本。新版本的提示词快照记录模板版本、输入与模型渠道，编辑还记录来源版本；快照不对模板版本建立外键，模板清理不影响已有文案历史。

## Considered Options

- 将文案写进套图方案或图片任务卡：会把独立文案绑定到无关的图片任务，且使历史和失败状态难以区分。
- 在模板内写死平台限制或仅依赖模型遵守：平台规则变化时需要重新发布模板，无法确定性拒绝超限或违规文案。
- 原地覆盖最近文案：丢失生成与人工编辑的历史，无法比较或找回旧版本。

## Consequences

- 两个入口复用 `/api/listing-copies` 与同一个文案结果编辑器；批次结果通过 `studio-state.listingCopy` 找到附加文案。
- 用户在独立页和批次抽屉都可以逐项复制文案、编辑最新版本并另存，或重新生成整份文案；旧版本仍可查看和复制。
- 上线前需发布文案模板，并定期复核平台文案规则。发布和规则变更不追溯修改已有版本。
