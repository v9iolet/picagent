# 首页商品建档 Agent、商品库与图片库去上传图调整

产品开发首次录入新品资料与下游美工创作（商品套图、上架文案、爆品图复刻及后续 A+ 详情、生视频）之间缺乏统一的商品事实载体，导致美工每次创作重复手填参数，且套图配置栏混用了客观商品事实与单次作图指令。本决策新增置顶「首页」建档 Agent 与独立「商品库」，通过不可变快照向各创作工具注入商品事实，并将图片库收敛为仅沉淀 AI 生成资产。本决策修订 [ADR 0006](0006-suite-one-click-studio.md) 与 [ADR 0009](0009-product-replica-studio.md) 中关于默认入口、资源库实拍原图选择及图片库收录范围的条目。

## 决策

- **主导航与根路由调整。** 左侧常驻导航顺序改为 `首页（/） → 创建（/create/suite） → 商品库（/products） → 图片库（/assets） → 模板库（/templates） → 配置（/settings）`。根路径 `/` 与左上角品牌入口默认落到 `首页`，不再重定向至 `/create/suite`。
- **首页 Agent 专职新品信息建档。** 一期首页居中对话框不直接执行生图任务，专职承接文字粘贴、UTF-8 `.txt` 文件（单文件 ≤200KB，单轮最多 3 个）与供应商参考图（0–6 张），调用视觉/规划模型（独立模板阶段 `product_onboarding`）抽取结构化商品信息卡草稿，并在单轮回复中合并追问所有缺失必填项。发起对话后页面展开为「左侧多轮对话追问 + 右侧实时可编辑商品信息卡表单」双栏；未发消息时展示居中建档对话框、创作功能快捷入口、未完成建档草稿与最近商品信息卡。
- **建档会话与商品库单向流转。** 首页保留未保存的 `draft` 建档会话以便中断后继续补全；确认保存到商品库后创建 `published` 商品信息卡，原会话标记为 `completed` 转为只读，并提供跳往商品套图、爆品图复刻的快捷入口。已发布商品卡的后续修订、归档（`archived`）及空白表单直接新建统一收口在「商品库（`/products`）」，避免会话与表单双写覆盖。
- **商品信息卡字段分层与事实边界。** 商品信息卡只保存跨工具通用的客观商品事实与供应商参考图，不含单次生图的版式或风格提示词，且不设商品类目与内部 SKU 字段：
  - **6 项入库必填**：商品名称、核心卖点（多条列表）、规格参数与尺寸重量、材质与工艺细节、适用人群与使用场景、包装清单/配件说明（无额外配件商品允许填写「单品本体 ×1，无额外配件」等显式确认值）。
  - **3 项选填与扩展预留**：用户痛点与自身对比数据（服务套图对比图及后续 A+ 详情）、使用方法/动态演示亮点（服务使用维护图及后续生视频脚本）、认证资质与宣传禁忌（服务跨境合规与上架文案）。
- **供应商参考图与生图实拍原图物理隔离。** 产品开发在首页或商品库上传的供应商参考图（0–6 张，首图为封面）仅用于建档识别与商品库认款展示，独立存储于商品卡路径下，不进入图片库（`/assets`），也不在下游选卡时流入生图配置栏；下游创作所需的商品实拍原图与参考图统一由美工在对应功能配置栏本地上传，保证生图外观质量。
- **下游选卡绑定与不可变快照。** 一期接入 **商品套图（自动联动同批次上架文案）** 与 **爆品图复刻**（生图画布暂不改造，A+ 详情与生视频本期仅做商品卡字段预留）。配置栏支持选填绑定最多 1 张 `published` 商品信息卡，批次默认名称优先采用商品卡名称，同时保留不选卡直接手填的临时散单用法；手填文本仅随当前批次保存在生成记录快照中，不自动创建商品卡，套图兜底补录（`waiting_human_input`）也不反向改写商品库。批次提交时服务端冻结当时的 `productCardSnapshot`（含 `revision`）；商品套图将商品卡快照注入 `human_supplement`（事实），将配置栏文本框专用于本次补充说明与 `emphasis_requirements`（指令），消除原单一字段事实与指令混用。
- **图片库仅保留 AI 生成资产（修订 ADR 0006、ADR 0009）。** 图片库（`/assets`）移除 `input_image`（商品实拍原图）收录与筛选，仅保留 AI 生成与派生资产（AI 生成结果、白底底图、过程图、爆品图反推）。爆品图复刻配置栏去掉「从资源库选择产品原图」，新建复刻批次仅接受美工本地上传产品原图；生图画布的图片库选择器仅列出已发布 `base_image`（白底底图），同时保留画布本地上传原图能力。历史批次与历史画布任务已持有的旧引用保持只读可渲染。

## Considered Options

- **让首页 Agent 直接对话出图**：需在聊天流内重做套图与复刻的异步进度、缺事实恢复与单卡编辑状态机，且偏离「上游开发建档 → 下游美工跨工具复用」的核心分工。
- **下游手填卖点自动写入商品库**：单次测试词与构图指令会产生大量重复未核验卡片，污染公共商品库。
- **选卡时自动将供应商图带入生图原图区**：供应商随手拍或带水印截图画质不可控，直接作为生图外观真值会拉低成品质量。
- **在商品信息卡中保留商品类目（`category`）或内部 SKU（`skuCode`）**：模型自由生成的类目文本缺乏跨轮次与跨同品类的幂等一致性，而预置固定电商类目字典会引入额外维护负担且下游生图/文案管线直接从商品名称与客观事实即可获取品类语义；内部 SKU 对视觉与文案生产无实质增益，故一并移除。
- **图片库继续混入上传原图仅改默认筛选**：用户明确要求图片库只沉淀生成的图片，且创作原图统一由美工当场本地上传，故直接移除图片库对上传原图的暴露。

## Consequences

- 迁移新增商品卡、商品卡供应商图与首页建档会话/消息表，并扩展 `prompt_library` 阶段约束支持 `product_onboarding`。
- 商品套图关联完整 6 项必填事实的商品卡后，主图、卖点图、场景图精确组在常规配置下直接通过结构规划事实门禁，避免与首页建档追问重复；`waiting_human_input` 仅作未选卡或特殊配置下的兜底门禁。
- 需同步调整现有图片库、生图画布资源选择器与爆品图复刻中断言 `input_image` 资源库选择的相关契约与浏览器测试。
