# 工作台交付视图、画布风格覆盖与外壳统一

PicAgent 将成品展示板（`gallery` 模式）从 XYFlow 节点画布中解耦，改为面向电商交付验收的只读货架仿真预览与分组网格视图，并按“编辑子卡片终版 → 父任务卡终版 → 最新编辑子卡片当前版 → 父任务卡当前版”的规则逐坑位归并交付图，支持附带 `manifest.json` 溯源清单的 ZIP 打包导出。同时，在创作板中引入方案级“画布风格覆盖”字段：服务端持久化该覆盖并在提交后续生图请求时前向替换任务提示词中的 `全局风格卡：` 段落写入新快照，不篡改已确认的结构计划快照、单卡草稿正文或任何历史图片版本快照。此外，全站统一为单一顶栏与 56px 极窄常驻侧栏外壳，创作板采用三泳道布局与选中高亮血缘降噪，不再机械沿用早期静态 HTML 原型中的全量连线与“接口预留”占位。

## Considered Options

- 成品展示板继续保留在 XYFlow 中仅做只读拖拽：实现成本低，但缺乏电商主图轮播与详情长图拼接的交付验收观感，且父卡与编辑子卡并列会导致同一坑位重复导出。
- 编辑画布全局风格时直接批量改写所有任务卡 `promptDraft`：容易覆盖设计师在单卡中微调好的局部提示词，且混淆全局风格前缀与单卡草稿的职责边界。
- 创作板与爆品图反推保持无侧栏沉浸态：多出 56px 横向空间，但导致各页导航割裂、两套顶栏 CSS 并存，降低全链路工作台的一致性。

## Consequences

- 服务端需新增方案级 `styleOverride` 持久化字段与更新接口、成品 ZIP 导出接口（含 `manifest.json` 溯源清单），并移除前端对 `styleGuide` 的重复前缀拼接。
- `tests/workbench-ui.ticket08.test.ts` 中强绑定旧原型全量连线和旧 DOM 结构的源码正则断言需同步更新，核心领域契约测试（两阶段规划、不可变快照、框架无关 `EditSnapshot`、版本血缘）保持不变。
- `docs/原型基准说明.md` 不再对 V1.2 之后的页面外壳与成品交付形态施加机械约束。
